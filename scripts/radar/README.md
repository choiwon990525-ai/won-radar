# WON 레이더

발로란트·AI 소식을 하루 3~4번 모으고, 발로란트 꿀팁 영상(YouTube 공식 API)과 전략·라인업·메타 레퍼런스를 함께 보여 주는 앱.

- 앱 주소: https://choiwon990525-ai.github.io/won-radar/ (꿀팁 탭 바로 열기: `#tips`)
- 이용 안내 · 개인정보처리방침: `radar/privacy.html` → https://choiwon990525-ai.github.io/won-radar/privacy.html
- 피커스 어드밴티지 3D: https://choiwon990525-ai.github.io/won-radar/peek/
- 예전 주소(choiwon990525-ai.github.io/choiwon990525/)는 닫음 (2026-10-22 옮김). 예전 주소로 폰에 깔아 둔 앱은 지우고 새 주소에서 다시 설치
- 폰에 설치: 아이폰은 Safari 공유 → 홈 화면에 추가, 안드로이드는 Chrome 메뉴 → 앱 설치

## 어떻게 도나

1. `.github/workflows/radar.yml` 예약은 3시간마다(KST :17분)지만, GitHub가 늦추거나 건너뛰어서 실제로는 하루 2~4번 돈다 (2026-10-31~11-09 기록: 간격 4~11시간). 그래서 데이터의 `next_hours` 는 8 (앱의 '늦음' 표시 기준 = 8시간 + 1시간 30분). 하루 넘게 수집이 없으면 앱 머리에 '수집 멈춤'.
2. 단위 시험(`python3 -m unittest discover -s tests -t .` — 인터넷 없이, 가짜 유튜브 응답만)이 먼저 돈다. 실패하면 그 회차는 배포 안 함.
3. 지난 결과를 `gh-pages` 에서 가져온다. 못 가져오면 그 회차는 멈춤 (빈 것으로 시작하면 쌓인 소식 · 꿀팁 코드와 주 번호가 사라져서).
4. `collect.py` 가 `sources.json` 의 피드를 읽어 `data.json` 을 만든다 (14일 보관 · 공식 패치 노트는 45일 · 분류마다 개수 한도 `max_items_by_cat`).
5. `tips.py` 가 `tips_sources.json` 의 채널 · 검색어로 꿀팁 영상을 모아 `tips.json` · `tips_week.json` 을 만든다 (아래 '꿀팁').
6. `check_refs.py` 가 레퍼런스 링크를 7일에 한 번 다시 연다 → `refcheck.json`.
7. `radar/` 화면 파일과 데이터 파일을 `gh-pages` 로 배포 → GitHub Pages 가 앱 주소로 보여 줌. 배포는 `main` 에서 돈 실행만 (다른 가지에서 손으로 돌리면 시험만).

## 웹에서 가져오는 규칙

- **robots.txt 를 지킨다.** 막힌 주소는 열지 않는다. 링크 점검은 막힌 곳을 '자동 확인 불가'로 표시만 한다.
- **브라우저인 척하지 않는다.** User-Agent 는 `WON-Radar/1.0 (+저장소 주소)` 하나.
- **유튜브는 공식 API 로만.** 채널 페이지 · 검색 결과 · 채널 피드(RSS) 같은 유튜브 페이지는 열지 않는다 (API 약관 · robots.txt). 그래서 소식(`sources.json`)에는 유튜브가 없고, 링크 점검도 유튜브 링크는 건너뛴다. 시험(`tests/test_collect_refs.py` RulesTest)이 코드에 막힌 유튜브 주소나 가짜 브라우저 이름이 들어가면 실패한다.

## 꿀팁 (YouTube 공식 API)

| 무엇 | 어떻게 |
|---|---|
| 키 | 저장소 Settings → Secrets → Actions 의 `YOUTUBE_API_KEY` (구글 클라우드 프로젝트 won-radar · YouTube Data API v3 만 허용 · 결제 계정 없음). 키는 요청 머리(X-Goog-Api-Key)로만 보내서 주소 · 로그 · 데이터 파일에 남지 않는다. 키가 없으면 새로 안 모으고, 지난 목록에서 기한 지난 것만 지운다 |
| 무엇을 모으나 | `tips_sources.json` 의 채널 26개(학원 · 유료 강의 회사 채널은 뺌) 새 영상 + 검색어 68개를 돌려 가며 찾은 영상. 검색어는 위에 있을수록 먼저 (매뉴얼북 빈 곳 순서) |
| 붙는 표시 | '어디서 찾았나'(채널 · 검색어)와, 검색어마다 미리 정해 둔 '넣을 칸 제안'(`to`: `mg:<맵>:offrefs·wallrefs·tiprefs` · `lane:<요원>:<맵>` · `agent:<요원>`)뿐. 영상 종류를 짐작해 붙이지 않는다 (API 정책 — 콘텐츠 유형 추정 금지). 채널 묶음(꿀팁·강의 등)은 코치가 정한 채널 분류 |
| 거르기 | 공개 영상만 · 아동용 · 생방송 · 예정 방송 빼기 · 제목 거르기(`exclude_title` — 하이라이트 · 매드무비 · 스킨 · 버그 등) · 뺄 채널 · 소속 낱말 (아래 Secret) |
| 기한 | 영상 정보는 7일마다 다시 받아 덮어쓰고, 29일 넘게 다시 받지 못한 영상은 지운다 (API 정책 30일). 조회수 같은 통계는 받지 않는다. 앱도 29일 넘은 꿀팁 파일은 보여 주지 않는다 |
| 하루 몫 | 레이더가 스스로 멈추는 한도: 검색 하루 10번(실행마다 3번 · 코드를 올릴 때 도는 push 실행은 검색 안 함) · 그 밖 하루 3,000단위. 구글 몫(검색 100 · 단위 10,000)에 한참 못 미침. 하루는 태평양 시각 자정(한국 오후 5시, 여름엔 4시)에 바뀐다 |
| 이번 주 후보 | 한국 시각 월요일에 바뀌는 주마다 15개까지 번호를 매긴다 (검색 결과 12개까지 — 검색어마다 2개 · 채널마다 2개, 그다음 '이번 주' 채널 새 영상 채널마다 1개 — 1분 넘는 것만, 쇼츠는 앱 '전체'에서 봄). 검색까지 한 실행에서 고른 목록은 그 주 동안 그대로, 한 번 낸 영상은 다시 안 냄. `tips_week.json` 에는 번호 · 코드 · 영상 id · 넣을 칸 제안 · 찾은 곳만 (제목 없음) + 지난 4주 |
| 공개 파일 | `tips.json` · `tips_week.json` 은 gh-pages 에 공개. 뺄 채널 · 걸러 낸 영상 id 는 파일에 쓰지 않는다 |

### 매뉴얼북으로 보내기 (코치 → Claude)

1. 앱 꿀팁 탭 '이번 주' 에서 번호를 보고 '답 틀 복사' → 예: `레이더 꿀팁 2026-W46 (1~15번) — 빼: 2, 5 / 칸 바꿈: 7 → 라인전 / 나머지 OK`
2. Claude 는 매뉴얼북 작업에서 `tips_week.json` 으로 번호 → 영상 id 를 찾고, 영상 제목 · 채널은 **oEmbed 로 다시 받는다** (API 로 받은 정보는 레이더 앱 밖에서 쓰지 않음). oEmbed 200 인 것만, 매뉴얼북 규칙대로 넣고 시험 · 전후 사진 → 코치 OK → 배포.

### Secret (선택 · 저장소에 안 적음)

| 이름 | 무엇 |
|---|---|
| `RADAR_SKIP_CHANNELS` | 뺄 채널. `UC…` 채널 id 또는 `@핸들`, 쉼표로. 핸들은 실행마다 다시 찾는다 (못 찾으면 수집 소스에 '뺄 채널 n개를 못 찾았어요' — 어느 핸들인지는 안 적음) |
| `RADAR_BLOCK_WORDS` | 영상 제목 · 채널 이름 · 설명에 있으면 빼는 낱말, 쉼표로 (소속 기관 이름 등) |

## 자주 하는 일

| 하고 싶은 것 | 방법 |
|---|---|
| 소식 소스 추가·삭제 | `sources.json` 에 한 줄 추가. `cat` 은 `valorant`/`ai`, `group` 은 앱의 분류 칩 이름. robots.txt 가 막지 않는 RSS · 사이트맵만 (사이트맵은 `sitemap: {pattern, title}`) |
| 꿀팁 채널 · 검색어 추가 | `tips_sources.json` 의 `channels`(@핸들 · 이름 · 묶음 · 언어 · `weekly`) · `queries`(id · 검색어 · 언어 · 이름 · `to` · `map`). 시험이 모양을 확인함 |
| 지금 바로 수집 | GitHub → Actions → "WON 레이더 수집" → Run workflow (main) |
| 레퍼런스 갱신 | 노션 「📚 전략·라인업·메타 레퍼런스」에 행 추가 후 Claude에게 "레이더 레퍼런스 갱신해줘" → 노션 행을 `notion_refs_export.json` 으로 내보내고 `build_refs.py` 로 `radar/references.json` 을 다시 만듦 (공개 저장소라 '용도'·'반' 칸은 내보내지 않음 — 아래) |
| 레퍼런스 후보 추가 | `ref_candidates.json` 에 한 줄. 다음 수집 때 링크를 확인함 (유튜브 링크는 점검 안 함) |
| 매일 Claude 브리핑 켜기 (선택, API 요금 발생) | Settings → Secrets → Actions 에 `ANTHROPIC_API_KEY`. 하루 한 번 Claude Opus 5.5 가 소식 제목만 보고 3줄씩 요약 (꿀팁 영상 정보는 브리핑에 안 씀). SDK 는 `anthropic==2.6.0` 고정 |

소스가 실패하면 앱 맨 아래 "수집 소스" · "꿀팁 수집"에 빨간 점으로 표시되고, 나머지는 그대로 돈다. 꿀팁 수집이 통째로 실패해도 소식은 배포되고 지난 꿀팁 파일을 그대로 둔다.
레퍼런스 링크 점검: '링크 확인 안 됨'은 실제로 안 열린 것, '자동 확인 불가'는 사이트가 자동 점검을 막았거나(HTTP 401·403·429) robots.txt 가 막아서 열어 보지 않은 것(브라우저로는 열림).

## 공개 저장소에 올리지 않는 것

이 저장소는 공개라 누구나 볼 수 있다. 학생 기록 · 개인정보는 이 저장소에 없다.

- 레퍼런스의 '용도'(use) · '반'(classes) 칸과 이름 · 메모 속 반 이름은 넣지 않는다 (노션 원본에만 있음).
  - `build_refs.py` 는 들어온 파일에 이 칸이 있으면 멈추고, 환경 변수 `RADAR_HIDE_WORDS`(쉼표로 나눈 반 이름 — 저장소엔 안 적음)가 있으면 이름 · 메모 속 반 이름을 지운다.
  - 수집 워크플로가 배포 전에 `build_refs.py --check` 로 한 번 더 본다. 반 이름까지 보려면 Secret `RADAR_HIDE_WORDS` (선택). 걸리면 그 회차는 배포 안 함 → Actions 에 빨간 표시.
- 학생 이름, 소속 기관 이름, 뺄 채널 목록, 열쇠(API 키 등)는 넣지 않는다 — Secret 에만. 시험이 저장소에 키 모양 글자가 있으면 실패하고, 워크플로도 배포 파일에 키 모양 글자가 있으면 멈춘다.
- 저장소에 60일 동안 변화가 없으면 GitHub가 예약 실행을 끈다 → 앱에 '수집 멈춤'이 뜨면 Actions 에서 다시 켠다.
